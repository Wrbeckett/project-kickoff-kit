# KICKOFF.md: instructions for Claude (new project)

You are setting up a brand-new project with the Project Kickoff Kit. The person who connected this folder is the **owner**. Follow these steps in order. Write for the owner in plain words: short sentences, exact menu and file names, no jargon. Never assume anything you weren't told; ask.

**Finding the kit:** the files named here ("03 Templates/…", "07 Join or take over a project/…") are in the Project Kickoff Kit, wherever this person has it: (1) **installed as a plugin**: the project-kickoff skill's own folder holds the whole kit (in its kit/ subfolder); (2) a **connected "Project Kickoff Kit" folder**; (3) the kit's **GitHub page** (https://github.com/Wrbeckett/project-kickoff-kit; read the raw files). Use the first you can reach and say which. If none, ask the owner to install the plugin or connect the folder, and don't build anything until the full kit is reachable.

## Rules for the whole kickoff
- **Ask, don't assume.** If something is unclear, missing or contradictory, ask. Use the multiple-choice question tool when you have it (2–4 options, your recommendation first), otherwise numbered questions.
- **Everything is a default.** The kit's structure, names, rhythm, models and templates are starting points. If the owner wants something different, do it their way and record it in PROJECT-CHOICES.md, so nothing later (reviews, upgrades) undoes it.
- **Ask in rounds** of 3–5 questions. After each round, say in one or two lines what you understood, then ask follow-ups only where an answer opened something up. Stop when you can fill every part of the blueprint (step 3).
- **Nothing is created, connected, bought, posted or deleted without the owner's OK.** Show the plan, then build.
- **Check every file you write** (open it, or compare a checksum) and tell the owner where it is.
- **Design for the usage budget.** Every session, scheduled task and report uses part of the owner's weekly Claude usage. Size the setup to the plan and the share the owner gives you (03 Templates/USAGE-PLAN-template.md), say what each scheduled run is likely to cost (light / medium / heavy), and make sure the owner won't run out mid-week.
- **Match the model to the job.** Recommend a Claude model and effort level for every session, scheduled task and main kind of work (03 Templates/MODEL-GUIDE-template.md; kit defaults in "06 Models and sessions cheat sheet"). Recommend only models the owner's plan has, and Fable only with the owner's OK where it uses paid usage credits. Smaller models for routine runs help the project stay inside its usage share.
- Keep the whole thing as light as the project needs: recommend a **setup level** (03 Templates/Setup levels.md: Solo, Standard or Team) and build only what it calls for. A one-person, two-week project is Solo: one session and a handover, not five sessions and four reports.
- **Sensitive information: the owner decides the rule.** Always ask question bank §5b (personal information, the organization's privacy or AI policy, NDAs) and write their answer down in their words as rule 15. Don't decide it for them. Until the owner sets it, keep personal information about other people out of project files, chats, trackers and scheduled tasks; this is a temporary hold, logged as an open question with a date, not the kit deciding the rule.

## Step 1: Look around (silent)
- List this folder. Note anything already in it. If it holds a handover pack ("HANDOVER-PACK - …"), stop and follow 07 Join or take over a project/TAKEOVER.md (or JOIN.md for a JOIN pack) instead.
- Read the owner's **MY-DEFAULTS.md** (their own filled-in copy of the kit's MY-DEFAULTS-template.md, in any folder connected to this chat; ask whether they have one). Use it as the starting answers: don't re-ask what it covers, but confirm it in the summary.
- Check which tools this chat has: connected folders, connectors (calendar, email, Drive, Dropbox, GitHub, design tools…), scheduled tasks, artifact/doc tools, browsers, skills, and **plugins** (the ones already installed, and, where you can search, ones that fit the project). You'll recommend what fits later.
- **Check whether this chat is inside a Claude Project, with the project folder connected. If not, stop here** and walk the owner through making the Project and folder first (step-by-step PDF, steps 1–3; about 3 minutes), then ask them to start a new chat inside it and type "start a new project" again. Don't begin the interview outside a Project: this chat becomes the project's Lead session, so it must live in the Project.
- Check which computer this chat is linked to (get_device_info, if available). If it isn't the owner's home computer, or they haven't picked one, say so before anything is scheduled.
- Check which model this chat runs on. The kickoff works best on Opus at Medium effort (Sonnet on the Free plan). If the chat is on a smaller model, suggest switching before the interview (click the model name next to the send button).

## Step 2: The interview
**Starter presets:** if the project looks like an event, a course, a website, a client job or research, offer the matching preset from 03 Templates/Presets/ first ("This sounds like an event; want to start from the event preset?"). Its answers are suggestions to confirm, never decisions; skip the questions it settles once the owner confirms them.
Use **"01 New project/Interview question bank.md"** from the kit (see "Finding the kit"; if you can't reach it, use the topics below). Cover these areas, in this order, in rounds:
1. **The project:** what it is, why, who it's for, what "done" and "success" look like (with numbers if possible), hard deadlines.
2. **People:** who's involved, who decides, who does what, who else reads the reports (team, client, boss), and who besides the owner will give updates (they'll use UPDATES-INBOX.md, because only the owner can post in the Lead chat).
3. **Work:** the main kinds of work (e.g. build, design, writing, marketing, admin, research, teaching), what repeats (daily, weekly), what's one-off.
4. **Where things live:** files, accounts, websites, repos, apps, shared drives; what Claude may read and what it may change. **Home computer** (Mac or PC): which computer stays on for this project (question bank §4b).
5. **Rules and limits:** budget, approvals, things Claude must never do, privacy, brand or style rules, legal or school policies, and their **sensitive-information rule** (question bank §5b: always ask).
6. **Time and rhythm:** how many hours a week the owner has, best times of day, when they want briefs or reports, time zone.
   - **Claude plan and usage budget (always ask, question bank §6b):** which plan, when weekly usage resets, the share of weekly usage this project may use, other projects on the account, the owner's heavy days, whether usage has run out mid-week before, what to do if the project nears its share, and which models show in the owner's model picker (Haiku, Sonnet, Opus, Fable), whether Fable is included or uses paid credits, and any model they prefer or avoid.
7. **Communication:** how they want updates (short/long, PDF/chat), what they find annoying, preferred words for things, and anything in the kit they want to skip, rename or do differently.
8. **Risks and unknowns:** what could go wrong, what they're unsure about.
End the interview by reading back a 10-line summary and asking: "Is this right? Anything to add or change?"

## Step 3: The blueprint (show it, get the OK)
**Show it in sections, one at a time, and get an OK on each** before the next (changes are easy at this stage): (1) setup level, goal and folders; (2) sessions, models and trackers; (3) rhythm, usage plan and home computer; (4) tools and rules; (5) what could go wrong and open questions. Then write the whole thing to **PROJECT-BLUEPRINT.md** in the project folder. It covers:
- **Setup level** (Solo, Standard or Team; 03 Templates/Setup levels.md) and why. Everything below follows it.
- **Goal + success measures + deadlines.**
- **Folder structure:** start from "03 Templates/Standard folder structure.md" and adapt it. Name every folder and say what goes in it.
- **Sessions:** the lead session ("<Project> – Lead") plus only the work sessions the project needs (usually 0–4), each with its job, what it owns, and what it must never do. One session is fine for small projects.
- **Shared trackers:** only if work passes between sessions (e.g. a content tracker between Marketing and Design).
- **Rhythm:** morning brief? weekly reports? weekly review? Which day and time (use the owner's time zone; avoid exactly on the hour).
- **Usage plan** (fill 03 Templates/USAGE-PLAN-template.md): plan, reset day and time, this project's weekly share, every session and scheduled run with its rough cost (light / medium / heavy) and day, the expected week against the share, the efficiency rules, and a "pause first" list for weeks when usage runs high. **If the rhythm doesn't fit the share, cut it down before you show it.**
- **Home computer and unattended runs:** which computer holds the folders and runs scheduled tasks; which tasks need it (they use the project's files) and which can run in the cloud (no files needed); what the owner must set (sleep off while plugged in, app left open, folders synced). Prefer cloud-only runs where they do the job. **Laptop or a computer that's often off:** set a **work window** (days, start and end time) and put every task that needs the computer inside it, spaced out, the longest first; add a cloud-only reminder task before the window (phone notification and/or email, as the owner chose) listing what will run, and have the last task in the window send a "done, you can close it" message. If the tasks don't fit the window, cut or move them before showing the blueprint.
- **Model plan** (fill 03 Templates/MODEL-GUIDE-template.md, starting from the kit's "06 Models and sessions cheat sheet"): for every session, scheduled task and main kind of work, the model and effort, why, and when to move up or down. Routine scheduled runs on smaller models; judgment work on Opus. Check it against the usage plan.
- **Tools:** plugins, connectors, skills and apps worth adding (plugins are Anthropic's and others' ready-made workflow packs, e.g. Small Business, Operations, Marketing), each marked already installed or worth adding, with the reason, cost if known (a plugin is usually free, but the services it connects to may not be), and who sets it up. Every one is optional; the setup never depends on a plugin the owner doesn't have. Mark each **CLAUDE CAN DO (with your OK)**, **YOU DO (step by step)** or **NEEDS A CONNECTOR**.
- **Rules:** the owner's never-do list + the kit's standard rules (03 Templates/WORKFLOW-RULES-template.md).
- **What could go wrong** (about 5 minutes): imagine it's the deadline and the project didn't work out. List the 3–5 likeliest reasons (start from the preset's list, if one was used), each with an early warning sign and what the setup does about it (a rule, a check in the weekly review, a decision date). These go in the handover's §11.
- **Open questions** still left.
Ask: "OK to build this? Change anything?" Build only after a clear yes to the whole blueprint.

## Step 4: Build it (after the OK)
1. Create the folders.
2. Fill the templates from "03 Templates" into the project folder (or into the Claude Project's docs if the owner prefers): PROJECT-HANDOVER.md, one SESSION-BRIEF-<name>.md per session, WORKFLOW-RULES.md, trackers if needed, WORKFLOW-REVIEW.md, CHEAT-SHEET.md (with each session's model and effort), USAGE-PLAN.md, MODEL-GUIDE.md, and UPDATES-INBOX.md at the Team level (plus the shared-folder set: CHANGES.md, ASSETS.md, People/<name>/ folders the shared-files-and-owners table with protected files marked, the project lead, and the backup routine: version copies before edits and a weekly snapshot task on the lead's home computer; kit › 09 Shared folder), plus PROJECT-CHOICES.md at every level (what this project does differently from the kit, including anything taken from MY-DEFAULTS.md). Make only the files the setup level calls for (Solo: the handover with §13 filled in instead of USAGE-PLAN and MODEL-GUIDE). Fill in the handover's kit version line from the kit's README. Put each session's model and effort at the top of its brief.
3. Make **"<Project> - START HERE.pdf"** in the project folder: what the project is, the folders, the sessions (what to ask each, and which model and effort to pick), the weekly rhythm, the owner's first 5 steps, and how to change anything later (tell Lead "change: …"). Look at every page before saving.
4. Make **"<Project> - Session prompts.pdf"**: for each extra session, the exact chat name to use and the one prompt to paste (template in "04 Prompts to copy", Prompt 3), plus the model and effort to pick before pasting.
5. **Before scheduling, check you're on the home computer.** A task that uses the project's files runs on the computer this chat is linked to. If this chat isn't on the home computer, stop and tell the owner to open this chat (or the Lead session) on the home computer first. Give tasks that don't need the files no computer at all. Then, with the owner's OK, create the scheduled tasks (briefs, reports, weekly review). Each one must work in a fresh chat: give it full instructions, make it read the handover first and update it last, and never let it act on money, posting, emails, deleting or deploying. Follow the usage plan: heavy runs early in the usage week (right after the reset), never stacked at the same time, and every run stops early with one line when there's nothing new. Set each task's model from MODEL-GUIDE.md if the scheduled-task settings offer a choice; if they don't, tell the owner which model it will run on and note it in MODEL-GUIDE.md. Work window: create the reminder as a cloud-only task (no computer), with the notification channel the owner chose (email only if they asked for it); give every computer task the catch-up rule ("if the previous run was missed, cover that period too"). For each task, tell the owner in one line: which computer it needs (or "cloud, no computer needed") and which approval setting it got. Record both in the handover's §9 table.
6. Check every file. List what you made and where.
7. **Fresh chat test** (2 min, the owner does it): ask the owner to open a new chat in the same Claude Project, connect the project folder and paste **Prompt 19**. It must answer from the handover alone: the goal and deadline, the top open item, and which session and model handle a typical job. If it can't, fix the handover and repeat.

## Step 5: Hand over
- This chat becomes the **Lead session**. Rename suggestion: "<Project> – Lead".
- Tell the owner, in 5 lines or less: what's set up, the PDF to open, the first session to start, and the first thing they should do today.
- Add a line to WORKFLOW-REVIEW.md: "Kickoff done <date>". The first weekly review checks how the setup is working.
- Anything about the kit itself that didn't work well goes to KIT-FEEDBACK.md if the kit folder is connected and writable; otherwise tell the owner in one line, so they can pass it to whoever maintains the kit.
