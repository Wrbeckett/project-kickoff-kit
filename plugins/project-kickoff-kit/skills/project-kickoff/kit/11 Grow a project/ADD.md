# ADD.md: instructions for Claude ("add to this project")

The owner (or project lead) wants to add a **new part** to a project that's already set up: a new kind of work, a new goal, a report, a routine, a phase. Help them decide **where it fits** in the project's setup and **what it needs**, then change only what's needed. Write in plain words. Never assume; ask.

**Finding the kit:** see "Finding the kit" in README.md (plugin, connected kit folder, or the kit's GitHub page).

## Rules
- Read first: PROJECT-HANDOVER.md, PROJECT-CHOICES.md, WORKFLOW-RULES.md, CHEAT-SHEET.md, MODEL-GUIDE.md, USAGE-PLAN.md (Solo: handover §13), and the briefs. Shared-folder projects: CHANGES.md first.
- Show only the **change**, not a new blueprint. Nothing is created, connected, bought or scheduled without the owner's OK. Respect PROJECT-CHOICES.md: never bring back something the owner turned off unless they ask.
- Everything you suggest is optional; the owner can say "smaller" or "not now".
- If the new part needs another person, run 11 Grow a project/PEOPLE.md ("add a collaborator") for them after this.

## Step 1: Short interview (1–2 rounds, 3–5 questions each; multiple choice where possible)
1. **What is it?** In a sentence or two. What does "working" look like (a number if possible)?
2. **One-off or ongoing?** A single job, a phase with an end date, or something that repeats (how often)?
3. **Who does it?** The owner, an existing session, a teammate, someone new?
4. **What does it touch?** Files, folders, accounts, apps, websites, people outside the project.
5. **When?** Deadline or start date; does it wait on anything already in the project?
6. **Privacy:** does it bring in new personal information about other people? If yes, ask question bank §5b for this part and check it against rule 15.
Skip anything the owner already said. End with a 3-line summary and "Is that right?"

## Step 2: Where it fits (recommend one, with the reason and the alternatives)
- **A job for an existing session** (same kind of work, same tools): add it to that session's brief.
- **A new session** (a different kind of work, different tools or model, or it would crowd an existing brief).
- **A tracker** (work passes between sessions or people).
- **A scheduled task** (it repeats and can run on its own; say which computer it needs, or cloud).
- **A separate project** (its own goal, people and deadline; it would double this project's size): suggest "start a new project" for it, with a link line in both handovers.
Also check: does the **setup level** need to move up (Solo › Standard › Team)? Does a **preset** (03 Templates/Presets/) cover this kind of work?

## Step 3: What it needs
- **Tools:** plugins, connectors, skills, apps; each marked already installed / worth adding, with the reason and cost note. Always optional.
- **Model and effort** for its session or task (06 Models and sessions cheat sheet).
- **Usage:** light / medium / heavy, and what it does to the week against the project's share (USAGE-PLAN.md). If it doesn't fit, say what to pause or shrink.
- **Home computer:** if it adds a scheduled task that needs files, which computer and when (work window on a laptop).
- **What could go wrong:** 1–3 risks, each with a warning sign.

## Step 4: The change plan (show it; build after a clear yes)
5–10 lines: where it goes, what gets added or changed (files, sessions, tasks), tools, model, usage, risks, and the first step. Ask: "OK to add this?"

## Step 5: Build (after the OK)
- Update only what the plan names: the handover (status, next steps, §9 tasks), the affected briefs or a new SESSION-BRIEF, CHEAT-SHEET.md, MODEL-GUIDE.md, USAGE-PLAN.md (Solo: §13), trackers, the setup level if it moved.
- New session: add its line to the Session prompts PDF (or give the prompt in chat), with the model to pick.
- Scheduled task: only with the OK, on the right computer, following the kit's scheduled-task rules.
- Log it: PROJECT-CHOICES.md ("Added: <what>, <date>") and, in shared-folder projects, CHANGES.md.
- Check every file. Finish in 3 lines: what was added, where it lives, the first step (or "what's next?").
