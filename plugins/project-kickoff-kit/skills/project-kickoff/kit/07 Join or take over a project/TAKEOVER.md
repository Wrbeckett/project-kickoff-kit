# TAKEOVER.md: instructions for Claude (taking over a project)

The person in this chat is the **new owner** of a project someone else (the **giver**) started for them, for example a consultant who gathered their needs and is now handing the work over. They have a handover pack. Use it as the starting point for the interview, then set the project up with the Project Kickoff Kit in the new owner's own Claude. Write in plain words. Never assume; ask.

**Finding the kit:** the files named here ("03 Templates/…", "07 Join or take over a project/…") are in the Project Kickoff Kit, wherever this person has it: (1) **installed as a plugin**: the project-kickoff skill's own folder holds the whole kit (in its kit/ subfolder); (2) a **connected "Project Kickoff Kit" folder**; (3) the kit's **GitHub page** (https://github.com/Wrbeckett/project-kickoff-kit; read the raw files). Use the first you can reach and say which. If none, ask the owner to install the plugin or connect the folder.

## Rules
- **The pack is a starting point, not the truth.** Only the new owner's answers count as [stated]. Facts labelled [GIVER'S NOTES], [CLAUDE'S SUGGESTION] or [VERIFY] are confirmed, changed or dropped with them, never copied in as decisions.
- **Don't re-ask what they've confirmed.** Ask only what's missing.
- Everything in the kit is a default; the new owner's choices win and go in PROJECT-CHOICES.md.
- Nothing is created, connected, bought, posted, sent or deleted without the new owner's OK. Never contact the giver yourself.

## Step 1: Look around (silent)
- Find the pack ("HANDOVER-PACK - …") and any files sent with it (in the connected folder or uploaded to this chat or Project). No pack? Ask for it; if there is none, follow KICKOFF.md instead.
- Whether this chat is inside a Claude Project (if not, explain how to make one) and which folder is connected.
- The new owner's MY-DEFAULTS.md, if connected. Which model this chat is on (Opus, Medium effort).

## Step 2: Go through the pack together (rounds of 3–5 items)
For each section of the pack:
- **[DECIDED] and [CONFIRMED BY …]:** list them; ask "still right?" in one go.
- **[GIVER'S NOTES] and [CLAUDE'S SUGGESTION]:** ask one by one, multiple choice where possible: keep / change / drop.
- **[VERIFY]:** ask.
After each round, say in one or two lines what you understood.

## Step 3: Fill the gaps
Use 01 New project/Interview question bank.md for every topic the pack doesn't cover (section 11 of the pack lists them). Always ask:
- Claude plan, weekly reset, usage share; models in their picker (§6b).
- Setup level (Solo, Standard or Team); their time and rhythm; how they like updates.
- Their home computer (question bank §4b): the giver's computer won't run anything for them.
- Their never-do list and the sensitive-information rule.
- **The giver's role from now on** (the pack says what the giver offered): adviser or fully handed off; if adviser, what the giver may see or do, and how to reach them.
End with the kit's 10-line summary and "Is this right? Anything to add or change?"

## Step 4: Blueprint and build
Continue with KICKOFF.md from **Step 3 (the blueprint)** to the end: blueprint, approval, build, START HERE and Session prompts PDFs, scheduled tasks only with OK. Also:
- In PROJECT-HANDOVER.md: "Started by <giver> on <date>; taken over by <new owner> on <date> (handover pack: <file name>)". Keep the pack in "05 Reference".
- In PROJECT-CHOICES.md: anything the new owner changed from the pack.
- If the giver stays as adviser: add them to People and the cheat sheet ("questions about the history of the project → <giver>").

## Step 5: Hand over
This chat becomes "<Project> – Lead". In 5 lines or less: what's set up, the PDF to open, the first thing to do. Offer to draft a short "I've taken over" note the new owner can send to the giver (they send it).
