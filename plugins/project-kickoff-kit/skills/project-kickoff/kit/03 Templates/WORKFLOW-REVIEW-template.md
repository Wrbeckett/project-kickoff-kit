## How it works
1. All week, anyone adds ideas below: the owner ("workflow idea: …" to Lead), any session, any scheduled run that hits a snag, team members (IDEA: lines in UPDATES-INBOX.md).
2. The weekly run reads this file, the handover, all briefs, trackers, rules, the week's reports and the scheduled-task history, and writes "<date> Workflow review.pdf":
   - **A. Workflow:** what worked, what didn't (with evidence), the owner's ideas, recommendations (sessions added/split/merged, tasks moved, reports, rules).
   - **Usage:** the week's Claude usage against the project's share and pace (owner's Settings › Usage screenshot), which sessions and runs used the most, and cheaper ways to get the same result (update USAGE-PLAN.md).
   - **Models:** for each session and scheduled run, was the model and effort right? Move up: repeated misses or redo requests. Move down: easy routine runs, long waits for simple jobs. New Claude models released this week? Recommend changes; after the owner's OK update MODEL-GUIDE.md, the briefs and the cheat sheet.
   - **Numbers** (one line each, this week vs last): share of weekly usage used against the project's share; jobs redone or corrected; reports and briefs the owner actually read. Three numbers, no more.
   - **Runs:** any scheduled run that failed or never fired (computer asleep, offline, Claude app closed, folder not connected, waiting for an approval)? Each with the fix.
   - **What could go wrong:** any warning sign from the handover's §11 showing up? Add new risks.
   - **Growing:** ideas or requests that came up twice or more but don't fit any session: suggest "add to this project" for each; work that needs another person: suggest "add a collaborator".
   - **Setup level:** still right? Suggest moving up (or down) a level only with evidence.
   - **For the kit:** anything about the kit itself (not this project) goes to KIT-FEEDBACK.md if the kit folder is connected and writable, or the list below for the owner to pass on.
   - **B. Tools & resources:** plugins, connectors, skills, apps, processes that fit a real need (max 5; cost + effort; at most 1–2 new plugins, and only for a need seen this week).
   - **C. Audit:** quick scan of everything + one area in depth (rotation below).
   - Every item: **CLAUDE CAN DO (with your OK)** · **YOU DO (step by step)** · **NEEDS A CONNECTOR**.
   - One numbered decision list for the owner.
   - Respect PROJECT-CHOICES.md: don't re-suggest what the owner turned off unless there's new evidence, and say so.
3. Nothing changes until the owner answers ("OK 1, 3; not 2"). Lead makes the changes and logs them below.
