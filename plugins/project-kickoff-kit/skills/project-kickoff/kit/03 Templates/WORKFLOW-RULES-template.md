# <Project> workflow rules (all sessions + every scheduled run)
Approved by <owner> on <date>. The handover §5 points here. The owner's standing rules always win, and PROJECT-CHOICES.md overrides anything below. Remove, rename or rewrite any rule.

Keep only the rules this project needs; add your own.

1. **Numbered brief items.** The morning brief numbers every task for the owner. The owner updates the Lead session in shorthand ("done 3, 5; 9 tomorrow"). Lead matches the numbers, passes each update on and confirms in one line. Ambiguous → ask.
2. **Every decision has a deadline and a safe default:** "DECIDE by <day, time>: … If no answer: <default>." Never a default for money, posting, emails, deleting, deploying, terms, or changes to the workflow.
3. **One "do it now" window a day.** Steps only the owner can do (uploads, approvals, deploys, sign-ins) go in one block at the top of the brief, in order, with minutes each.
4. **New ideas during busy or frozen periods go to Lead**, which logs them for the right session and the right day.
5. **Weekly trim.** Lead moves finished items older than 7 days out of the briefs into ARCHIVE-LOG.md, so briefs stay short, and keeps PROJECT-HANDOVER.md to about 2 pages (older status and settled decisions move to ARCHIVE-LOG.md with a one-line pointer). Never moves open items, rules, lessons or task tables.
6. **Planned fresh starts.** When a chat gets long, slow or forgetful, it says "time for a fresh chat" and the owner opens a new one with Prompt 4.
7. **Report check after two weeks.** The owner says which reports they read; the rest get shortened or turned off.
8. **Browser fallback.** If one browser tool isn't connected, use the other available one instead of stopping; if none, add a setup step for the owner.
9. **Cheat sheet copies stay in step.** If the cheat sheet exists as a page, a file and a PDF, update all three together.
10. **Weekly review + audit.** Ideas collect in WORKFLOW-REVIEW.md all week ("workflow idea: …" to Lead). The weekly review checks the workflow with evidence, suggests tools and connectors, audits one area in depth (docs → sites → folders → shared files → accounts, rotating), and marks every fix CLAUDE CAN DO / YOU DO / NEEDS A CONNECTOR. Nothing changes until the owner says "OK 1, 3; not 2".
11. **Scheduled runs start from nothing.** Their instructions must be complete, read the handover first, update it last, and have a fallback if a tool or file isn't reachable (keep scripts they need in the project folder).
12. **Files:** never overwrite in place; write under a new, never-used name (with date and time), check it, then replace. Never delete; move to _to_delete.
13. **Usage budget.** This project uses up to <share> of <owner>'s weekly Claude usage (<plan>, resets <day, time>); details in USAGE-PLAN.md. Heavy jobs go early in the usage week; scheduled runs stop early with one line when there's nothing new; read only the docs a job needs; reuse saved scripts and templates instead of rebuilding; start a fresh chat when one gets long. If usage is ahead of pace mid-week, Lead tells the owner and suggests items from the "pause first" list (owner's OK).
14. **Right model, right effort.** Each session and scheduled run uses the model and effort in MODEL-GUIDE.md (also at the top of its brief). Set it before the first message (click the model name next to the send button). If a job misses the mark: check the prompt and files, raise the effort, then move up one model, and log it in WORKFLOW-REVIEW.md. Never switch to Fable where it uses paid credits without the owner's OK.
15. **Sensitive information.** <The owner's rule. Default:> no names, ID numbers, grades, accommodations, health or contact details of students, clients or staff in project docs, chats, trackers or scheduled tasks unless the organization's policy allows it; initials or codes where it does. Never in shared files or anything a scheduled run sends. **VERIFY** against the organization's policy.
16. **Updates inbox** (Team level, or whenever someone besides the owner gives updates). Only the owner can post in the Lead chat; everyone else adds updates to UPDATES-INBOX.md. Lead reads it at the start of every run, handles each line and moves it to Handled.
17. **Kit feedback.** Problems or ideas about the Project Kickoff Kit itself (not this project) go to KIT-FEEDBACK.md if the kit folder is connected and writable, otherwise to the "For the kit" list in WORKFLOW-REVIEW.md.
18. **The owner's choices win.** Everything here and in the kit is a default. PROJECT-CHOICES.md lists what this project does differently; it wins over every template, the rules above, the cheat sheet and kit upgrades. "change: …" to Lead: Lead says in one line which files it will update, waits for the OK, updates them all together and logs it there; "undo change <#>" reverses it. Never re-suggest something PROJECT-CHOICES.md lists as not used unless the owner asks or there's new evidence, labelled as such.
19. **Home computer.** <Computer name, Mac or PC> is this project's home computer. New sessions and scheduled tasks are created there. Before creating a scheduled task, check this chat is on the home computer; tasks that don't need the project's files run in the cloud with no computer. The owner keeps the home computer awake while plugged in, online, with the Claude app open and the folders synced. A run that can't reach the computer sends the owner a short message saying so instead of failing silently. **Work window** (laptops): <days, start–end>. Tasks that need the computer run only inside it; a reminder goes out <15/30/60> minutes before (<phone / email>); the last task sends "done, you can close it"; every computer task covers anything a missed window skipped.
20. **One owner per shared file** (shared-folder projects). The handover's "Shared files and owners" table says who owns each shared file; only the owner's Claude edits it. Everyone else adds an ASK: line to UPDATES-INBOX.md, or edits only their own tracker columns. Personal work stays in People/<name>/ until it's ready to share.
21. **Change log and current assets** (shared-folder projects). Before any job, read the new lines in 00 Admin/CHANGES.md since your last run (your brief records the last one read) and re-read the files they name; check for sync-conflict copies of files you'll touch and report them to the file's owner instead of choosing one. After changing a shared file, add one line to CHANGES.md. Use only the assets 04 Assets/ASSETS.md marks CURRENT.
22. **Project lead and protected files** (shared-folder projects). <Name> is the project lead. Files marked protected in the handover's owners table change only after the lead's OK (an ASK: line in UPDATES-INBOX.md, answered in the Lead chat), recorded in CHANGES.md as "approved by <lead>". Changing the lead needs the current lead's OK (Prompt 17). Where the sync service allows, protected folders are view-only for everyone but the lead.
23. **Backups.** Before editing a shared file, copy it to Archive/_versions/<file> <date time>. A weekly snapshot task zips 00 Admin, 03 Final and 04 Assets into Archive/Backups/ (keep the last 8; older ones go to _to_delete). Restores (Prompt 16) show the differences, save the current version first, and need the lead's OK.
